## 2. P0 — 工程缺陷修复（v1.7 第一步，先行合入）

### 2.1 CI 必须真实拦截失败

**问题**：两个测试步骤均 `continue-on-error: true`，测试红了 CI 仍绿，缺陷代码可直达 master 与 npm publish（release.yml 依赖同样的 `npm test`）。

**方案**：

```yaml
# .github/workflows/ci.yml
matrix:
  node-version: [18, 20, 22]
steps:
  - run: npm ci
  - run: npm test
  # continue-on-error 全部删除
```

**验收**：故意让任一测试失败 → CI failure；恢复后 CI 绿。

### 2.2 修复幽灵桌面端测试

**问题**：`npm run test:desktop` = `vite build && node scripts/run-tests.js test/desktop`，但 ① `test/desktop/` 目录不存在；② `run-tests.js` 根本不读 `process.argv`，参数被静默忽略 → 实际把同一批 17 个 CLI 测试又跑一遍，伪装成"桌面端测试"。CI 里 `xvfb-run npm run test:desktop` 因此是无效门禁。

**方案**：
1. `run-tests.js` 支持 glob 发现：用 `node:fs` 扫描 `test/*.test.ts`（+ 可选 `test/desktop/*.test.ts`），删除硬编码列表。
2. 若桌面端确无测试，先在 CI 中移除该步骤并在此记录，随后按 §3.3 补齐真实桌面端测试后再恢复。

**验收**：新增一个 `test/foo.test.ts` 无需改脚本即被 `npm test` 执行；`test:desktop` 要么跑真实桌面端测试、要么不存在该脚本。

### 2.3 补依赖声明

- `package.json` devDependencies 增加 `@types/node`（当前 tsconfig `types: ["node"]` 依赖传递安装，全新环境 `tsc --noEmit` 直接报 TS2688）。
- CHANGELOG 补 1.6.0 条目（TS/ESM 迁移 + Ink TUI 重构）。

### 2.4 文档对齐现实（一次性小 PR）

- README.md / README.en.md / CLAUDE.md：CommonJS 描述 → TS+ESM；`src/cli.js` → `src/cli.ts`（bin 指 `dist/cli.js`）；架构图补 `tui-ink/`、`swarm/`、`channels/`、`sandbox/`、`voice/`、`autopilot/`、`coordinator/` 等缺失目录；统一配置目录写法（代码实际使用 `~/.haxagent/`，见 `src/config/paths.ts`）。
- 删除或标注 README 中已不存在的行为描述。

**验收**：按 README 从零 clone → `npm install && npm test && npm run build` 全部成功；架构图目录与 `ls src/` 一致。

## 3. P1 — 质量提升（v1.7 主体）

### 3.1 真实 Lint

- devDeps 加 `eslint` + `@typescript-eslint/*`（flat config），`npm run lint` = `eslint src test scripts`；`typecheck` 保留独立脚本。
- 首轮先 `--max-warnings` 宽松（如 no-unused-vars 关闭），只拦截真问题（no-explicit-any 逐步收紧）。

### 3.2 测试覆盖补齐（按风险排序）

| 优先级 | 目标模块 | 理由 |
|--------|----------|------|
| 1 | `src/tools/registry.ts`（路径沙箱、isReadOnly、权限分类） | 安全边界，零测试 |
| 2 | `src/engine/agent.ts` 主循环（tool loop、compact/retry、中断） | 核心路径，仅有 system-prompt/tool-result 两块局部测试 |
| 3 | `src/memory/`（store CRUD/TTL/signature 去重、compact 阈值、relevance 打分） | 纯逻辑、易测、影响上下文行为 |
| 4 | `src/config/`（settings 合并优先级、profiles 切换） | 配置错误=全局限障 |
| 5 | `src/skills/registry.ts`、`src/plugins/registry.ts`、`src/hooks/registry.ts` | 扩展生态入口，frontmatter/manifest 解析易回归 |
| 6 | `src/api/retry.ts`、`src/api/provider.ts`（mock fetch，覆盖 15 provider 的注册与错误分类） | 已有 2 个测试，补齐 |
| 7 | `src/channels/adapter.ts` + 1 个 impl（mock fetch） | 双向化（F5）的前置 |

不追求行覆盖率数字，追求"每个 P0 行为至少 1 条断言"。配合 `c8`（或 node --test 内置 coverage）输出报告，先观察后设门禁（建议初始门禁：核心目录 `src/core`、`src/engine`、`src/tools` ≥ 60%）。

### 3.3 桌面端最小测试闭环

- `desktop/main/index.js` 的 IPC handler 提炼为可注入依赖的纯模块（approval 队列、session 生命周期），用 node:test 直接测。
- Vue 组件用已有 `@vue/test-utils` + `jsdom` 对 `ChatArea.vue` / `ApprovalModal.vue` 写 3-5 条渲染断言，恢复 `test:desktop` 真实门禁。

### 3.4 跨平台 CI

- matrix 增加 `windows-latest`、`macos-latest`（仅跑 `npm test`，桌面端测试只在 ubuntu + xvfb 跑）。
- `src/sandbox/win-sandbox.ts`、`macos-sandbox.ts`、`src/utils/shell-utils.ts` 至少有平台条件编译的 smoke 测试。

### 3.5 桌面端重构（可在 1.7 内做小半步）

- `App.vue`（1153 行）按组件域拆分：`useSession` / `useWorkspace` / `useAgentEvents` composables（沿用已有 `composables/` 目录习惯）。
- `desktop/main/index.js` 渐进 TS 化：preload 的 `haxAgent` API 先补 `.d.ts`，渲染进程获得类型提示。

### 3.6 清理

- 删除 3 处 `@deprecated`（`query.ts` L198、`errors.ts` L352、`tui-ink/types.ts` L203）及其兼容层。
- 评估 `--legacy` readline 路径退役：Ink TUI 已稳定，legacy 的维护成本>收益。1.7 先打 deprecation 警告，1.8 移除（README 已承诺"始终保留"则改为"1.9 前保留"，在 CHANGELOG 明示）。

## 4. 新功能展望（三波次）

### Wave 1（v1.7）— 上下文工程与可靠性

#### F1 语义记忆检索
- **现状**：`src/memory/relevance.ts` 仅关键词/title/tags 打分；`store.search()` 关键词匹配。
- **方案**：默认实现 BM25（零依赖、纯 TS，建倒排索引于 `.haxagent/memories`）；可选配置 embedding provider（复用现有 15 provider 注册表，新增 `embedding` 能力位）。`rankMemories()` 保持签名不变，内部切换策略。
- **验收**：`/memory search "登录鉴权"` 能命中不含该关键词但语义相关的记忆；无 embedding 配置时自动降级 BM25；新增 `test/memory-bm25.test.ts`。

#### F2 Prompt Caching 与成本可视化
- **方案**：Anthropic adapter 注入 `cache_control`（system prompt + 最近 N 轮工具定义打 breakpoint）；`/cost` 输出 cache hit/miss token 与节省金额（`src/engine/cost-tracker.ts` 已有底座，`src/pricing.ts` 已有价格表）。
- **验收**：连续两轮对话第二轮 usage 出现 cache_read tokens；`/cost` 显示"缓存节省 $x.xx"。

#### F3 Checkpoint / Undo 自动快照
- **动机**：`file.write`/`file.edit`/`shell.run` 均为破坏性操作，出错后无一键回滚。
- **方案**：`src/tools/registry.ts` 写类工具执行前将原文件快照到 `.hax-agent/checkpoints/<session>/<seq>/`（复用文件回收站思路）；新增 `/undo [n]` 与 `/checkpoint list` 命令；快照自动清理（保留最近 N=50）。
- **验收**：让 agent 改坏文件后 `/undo 1` 恢复原内容；快照目录有上限不膨胀。

#### F4 后台任务与完成通知
- **方案**：`src/tasks/manager.ts` 扩展后台运行（ detached agent task + 轮询/事件回调）；完成时经 `node-notifier`（已是 optionalDependency）+ channels 通知（打通 F5 前先用系统通知）。
- **验收**：`/goal` 长任务切到后台，终端继续可用；任务完成弹通知并写会话记录。

### Wave 2（v1.8）— 通道双向化与多端对齐

#### F5 Channels 双向网关（远程指挥入口）
- **现状**：11 个 channel 全部只有出站 `send()`（如 `feishu.ts` 仅发消息），本质是通知器。
- **方案**：新增 `src/channels/gateway.ts`——按 channel 配置拉起轻量 HTTP webhook receiver（飞书/钉钉/Slack 事件回调），消息经 allowFrom 鉴权后注入 AgentEngine 会话，回复走既有 `adapter.send()` 回投。与 F4 组合实现"IM 里远程指挥本地 agent"。
- **验收**：在飞书群里 @bot 发"跑一下测试"，agent 执行并把结果摘要回发到群；未授权用户消息被拒并记录。

#### F6 桌面端功能对齐
- 审批队列（多工具审批排队而非阻塞单条）、内联 diff 视图（CLI 已有 DiffView，桌面端复用逻辑）、skills/plugins 管理面板、swarm 任务监控面板。
- 依赖 §3.5 的 composables 拆分。

#### F7 Web Search 默认可用
- **现状**：`web.search` 需用户自配搜索 API。
- **方案**：内置默认 provider（DuckDuckGo HTML 免 key 兜底 + 可配置付费源），`/config web.search.provider` 切换。

### Wave 3（v1.9+）— Agent 编排深化

#### F8 子 Agent 并行执行
- `agent` tool 支持同一 turn 内并行 fan-out（Promise.all + 独立 QueryContext），结果汇总渲染；swarm in-process 后端复用该能力。

#### F9 Plan Mode 工程化
- todo 清单持久化（跨 compact 保留）、计划文件落盘可 diff、`/plan approve` 后按清单逐项执行并打勾（对接 F3 快照兜底）。

#### F10 生态分发
- `hax-agent skill install <git-url>` / `hax-agent mcp add <name>`（installer.ts 已有插件安装雏形，扩展到 skills/MCP registry 清单格式）。

#### F11 Opt-in Telemetry
- 匿名 usage 事件（provider/model/工具调用次数/失败率），`HAX_AGENT_TELEMETRY=0` 一键关闭；产出 `/stats` 本地 dashboard（桌面端优先展示）。
